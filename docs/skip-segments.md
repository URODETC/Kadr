# Пропуск опенинга и финальных титров

## Реализовано

- AniLiberty: поля эпизода `opening.start/stop` и `ending.start/stop` преобразуются в секунды `Playback.segments`. Работает прямой каталог и AniLiberty через экстрактор. Контракт проверен по установленному парсеру anicli-api (`aniliberty_parser.EpisodeSkipJson`).
- Остальные потоки: плеер читает главы через Shaka `getChaptersTracks()` / `getChaptersAsync()`. Используются только явные названия OP / Opening / Intro / Опенинг и ED / Ending / Credits / Титры. Если контейнер или манифест не предоставляет главы, меток не будет.
- Метки провайдера имеют приоритет над главами. Метки относятся к выбранной серии и версии потока; при смене потока главы загружаются заново.
- Во время интервала показывается кнопка пропуска. В титрах доступна также следующая серия, если она существует. Никакого таймера или автоматического перехода по началу титров нет. Обычный переход по окончании видео сохранён.
- Пропуск титров перематывает ровно к концу интервала, сохраняя сцену после титров. Переход к следующей серии помечает текущую просмотренной, обычный пропуск сохраняет позицию.
- Кнопку можно скрыть на время текущего потока. Предложения работают при перемотке назад, в полноэкранном контейнере Shaka и на мобильном экране. В нативном полноэкранном видео iOS HTML-кнопки могут быть недоступны.
- Отрицательные, пустые, пересекающиеся, нечисловые и выходящие за длительность метки игнорируются. Начало в нулевую секунду допустимо.

## Границы покрытия

Это система парсинга явных меток, без распознавания видео по изображению или звуку. Для немаркированного видео пропуск не предлагается: последние 90 секунд могут содержать сюжет. Метки одного перевода нельзя автоматически переносить в другой монтаж. Общая база таймкодов и ручная разметка пока не реализованы.

## Возможное расширение для немаркированных источников

Отдельный фоновый анализатор может сравнивать аудиоотпечатки начала и конца нескольких серий одной версии релиза. Кандидат должен повторяться в нескольких эпизодах и иметь устойчивые границы; одного затемнения, музыки или текста на экране недостаточно. Результат необходимо привязывать к версии файла, длительности, эпизоду и переводу. Проверенные результаты можно отдавать через тот же `Playback.segments`; непроверенные потребуют отдельного уровня уверенности и проверки человеком. Такой анализ потребует доступа к медиаданным и отдельного лимита CPU/трафика, которых нынешний экстрактор не использует.

## Проверка

`node --test tests/segments.test.mjs tests/player.test.mjs` — интервалы, границы, переходы по времени, неподходящие главы, приоритет меток.

`python -m unittest discover -s extractor -p 'test_service.py'` — сохранение полей в экстракторе и валидация.

Сборка: `npm run build`. Полный набор: `npm test` (требует разрешённого локального порта).
