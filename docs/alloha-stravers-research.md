# Исследование kinopoisk.cx / troutcdn / stravers

Дата: 13 сентября 2026 года. Только исследование; код и опубликованный сайт не изменены.

## Главный результат

Домен `stravers` соответствует провайдеру **Alloha** в публичном коде расширения MyShows Player. Это сильное свидетельство принадлежности плеера, но не подтверждение официальной связи зеркала с Кинопоиском. Замена домена открывает другой сервис.

Предоставленный адрес WebSocket сам по себе не является стабильным API фильма. Параметр `sid` выглядит как непрозрачный идентификатор сессии; правила его выдачи, срок жизни и привязки не установлены. Его значение не сохранено и не использовалось для запросов. Наличие WebSocket не доказывает передачу видео через него: содержимое сообщений не удалось наблюдать.

## Проверенные источники

1. [MyShows Player в Mozilla Add-ons](https://addons.mozilla.org/en-US/firefox/addon/myshows-player/), версия 1.9.1. Прочитан опубликованный XPI без установки или выполнения. Файл `content-scripts/myshows.js` определяет адреса с `alloha` или `stravers` как Alloha. SHA-256 исследованного XPI: `cb77c96fd2970734c63818d3ddb720e227feca9f2bfa430749bc8ddd238efb3e`.
2. [Исходный код kinopoisk-free](https://greasyfork.org/uk/scripts/589614-kinopoisk-free/code): распознаёт `troutcdn.site` как зеркало типа `bravo`; функция `rebuildBravo` забирает существующий `#film iframe`. Это свидетельство архитектуры зеркал из сторонней интеграции, а не просмотр DOM указанной страницы в этой проверке.
3. [Вход Alloha](https://alloha.tv/login): предлагает запросить доступ через форму; прямо указывает, что доступ получают владельцы сайтов. Бесплатность API, лимиты и условия встраивания этой страницей не подтверждаются.

## Три разных интерфейса

### Поиск материала

В расширении провайдер Alloha обращается к `https://api.apbugall.org/?token=<TOKEN>&kp=<KINOPOISK_ID>` либо использует параметр `imdb`. Код последовательно пробует POST и GET; ожидает JSON с `status: "success"` и `data`. Это обнаруженный контракт стороннего клиента, не официальная документация и не проверенный сейчас ответ сервера. Токены из расширения не использовались.

### Встраивание и управление

Клиент создаёт iframe с URL плеера, `referrerpolicy="origin"` и разрешениями autoplay/fullscreen/picture-in-picture. Изначальные сезон и серия читаются из параметров `season` и `episode` URL.

В исходнике используются JSON-сообщения `postMessage`: команда `{api: "seek", value: <seconds>}`, запрос `{api: "duration"}`; входящие события `timeupdate`, `duration`, `play`, `pause`, `seek`. Работа этих команд с текущим плеером в браузере не проверена. При собственной интеграции необходимо проверять `event.source` и точный `event.origin`, а исходящие команды отправлять на конкретный origin.

Часть отслеживания выбора сезона/серии в расширении опирается на host permissions и внедрение bridge. Обычный сайт не имеет этих полномочий: переносить этот механизм напрямую нельзя. Нужен поддерживаемый интерфейс самого iframe.

### Внутренний WebSocket

Наблюдаемый пользователем адрес имеет форму `wss://theatre.stravers.live/ws/?sid=<REDACTED>&v=2.1&t=<TIMESTAMP>`. Формат сообщений, бинарные кадры, порядок инициализации, выдача sid и связь с видеосегментами не установлены. Подключать такой URL к Shaka как HLS/DASH нельзя без выявленного поддерживаемого медиаресурса либо отдельного транспорта.

## Сетевые ограничения проверки

Указанная страница `https://fz9-1j1s2fz.troutcdn.site/4541515` не загрузилась: браузер показал тайм-аут, HTTP-клиенты — разрыв соединения или тайм-аут. Вход через `www.kinopoisk.cx/series/4541515/` также завершился тайм-аутом. Корень `https://theatre.stravers.live/` без идентификатора сессии ответил HTTP 404 с HTML-страницей ошибки.

Локальный DNS выдавал адреса диапазона 240.0.0.0/4, похожие на fake-IP локального прокси. Это не доказательство публичных адресов серверов или глобальной недоступности сервиса. Из этих ошибок нельзя делать вывод, что зеркало не работает у пользователя.

## Соответствие требованиям проекта

| Требование | Результат |
| --- | --- |
| Без загрузки видео на наш сервер | Возможна архитектура с внешним iframe; встраивание на нашем домене ещё не проверено |
| Только бесплатные источники | Бесплатный просмотр наблюдал пользователь; бесплатный доступ к API для нашего сайта не установлен |
| Русская речь, несколько озвучек сериала | Не проверено на указанной странице |
| Оригинальная аудиодорожка | Не проверено |
| Русские и оригинальные субтитры | Не проверено |
| Минимум 1080p, желательно 4K | Не проверено; наличие в каталоге не гарантирует качество всех серий |
| Готовые компоненты | Внешний плеер через iframe — наиболее короткий путь, если провайдер разрешает и технически поддерживает встраивание |

## Решение для следующего этапа

Исследовать официальный доступ Alloha и использовать возвращаемый URL готового плеера. Если будет нужен token, хранить его на сервере; через сервер получать только метаданные и iframe URL, а медиатрафик оставить между браузером и провайдером. Проверить разрешённые домены, CSP/X-Frame-Options, рекламу, события плеера и фактическое качество отдельно для нескольких фильмов и серий.

Для выяснения роли WebSocket требуется свежая рабочая сессия: тип и размер кадров, последовательность сообщений, соседние HTTP-запросы и адрес iframe без временных параметров. Не сохранять сырые HAR с cookies, sid и подписанными ссылками. До такой проверки прямой WS-адаптер и обещание всех требуемых дорожек/1080p/4K не обоснованы.
