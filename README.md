# Кадр / anime

Закрытый аниме-сайт для друзей. Next.js 16, React, shadcn/Radix, Shaka Player, Node.js 24 и SQLite. Не требует ChatGPT, OpenAI, Sites, Cloudflare или внешней системы авторизации.

До входа доступна только страница авторизации (и её статические JS/CSS/иконка). Страницы и API защищены на сервере. Публичной регистрации нет. Один суперадминистратор создаётся через консоль сервера; друзей он добавляет в разделе «Участники». Там же можно сменить пароль или удалить аккаунт — действующие сессии сразу отзываются. Пароль суперадминистратора восстанавливается только через консоль.

## Автоматический деплой

GitHub Actions: `dev` → проверки → PR в `main` → проверки → деплой по SSH. Настройка ключей, сервера и защиты ветки: [docs/deployment.md](docs/deployment.md).

## Деплой на своём сервере

Нужны Docker с Compose и HTTPS reverse proxy (Caddy/Nginx).

```sh
cp .env.example .env
# Укажите в .env настоящий APP_ORIGIN, например https://anime.example.org
# Оставьте COOKIE_SECURE=true для HTTPS.
docker compose build
docker compose run --rm app node scripts/admin.mjs create your_username
docker compose up -d
```

Команда создания запросит пароль скрытым вводом. Минимум 12 символов, максимум 128. Пароля по умолчанию нет; не передавайте пароль аргументом команды. Логин: 3–32 латинские буквы, цифры или `_`, регистр не учитывается. Не запускайте несколько команд первичного создания администратора одновременно.

Приложение слушает только `127.0.0.1:3000` на хосте. Пример Caddyfile для Caddy, установленного непосредственно на сервере:

```caddyfile
anime.example.org {
    reverse_proxy 127.0.0.1:3000
}
```

Направьте DNS домена на сервер, откройте 80/443 для Caddy. `APP_ORIGIN` должен точно соответствовать адресу сайта. Не открывайте порт Node наружу. Для reverse proxy в отдельном контейнере настройте общую Docker-сеть вместо адреса loopback.

Сброс пароля владельца с отзывом всех его сессий:

```sh
docker compose exec app node scripts/admin.mjs reset your_username
```

Обновление: `docker compose up -d --build`. Данные сохраняются в named volume `anime-data`; **не используйте `docker compose down -v`**, если хотите сохранить пользователей и историю просмотра. Одна реплика приложения; горизонтальное масштабирование с локальным SQLite не предусмотрено.

## Локальный запуск без Docker

Node.js 24+ (используется встроенный `node:sqlite`).

```sh
npm ci
cp .env.example .env
# Для локальной разработки: APP_ORIGIN=http://localhost:3000 и COOKIE_SECURE=false
node --env-file=.env scripts/admin.mjs create your_username
npm run dev
```

Открывайте именно `http://localhost:3000`, чтобы Origin совпадал. Для production без Docker: `npm run build`, затем `npm start` за HTTPS reverse proxy. Next загружает `.env`; консольный скрипт запускайте с `node --env-file=.env` либо передавайте окружение процессу.

## Источники аниме

Основной каталог работает через [anicli-api](https://github.com/vypivshiy/anicli-api), закреплённый на commit `ab79153c504dd1e6877749d64c978c362a2936a2` (версия проекта 0.12.0, MIT). Python-сервис `extractor` запускается вместе с сайтом через Compose; платные ключи не нужны. Подключены YummyAnime, AnimeGO, AniLib, AnimeVost, Sameband, Dream Cast и AniLiberty. YummyAnime выбран по умолчанию. У каждого источника собственная библиотека и набор переводов.

Выберите источник, найдите аниме, откройте серию и выберите озвучку либо вариант с субтитрами. Несколько плееров с одинаковым переводом различаются доменом в списке. Выбирается максимальное доступное качество; его можно сменить вручную. Сайт передаёт исходные названия переводов и не обещает японскую дорожку или субтитры у каждого релиза. anicli-api возвращает видеопотоки, но не отдельный каталог файлов субтитров: работают встроенные в поток/картинку субтитры и варианты, названные источником «Субтитры».

Настройки источника, сезона/релиза, серии, перевода и качества находятся внутри Shaka Player и доступны в полноэкранном режиме. Сезоны у источников обычно представлены отдельными релизами: используйте «Найти другой сезон», затем выберите точный результат. Сайт не объединяет похожие названия автоматически.

### Просмотр и история

- «Продолжить» на главной открывает последнюю серию с сохранённой секунды; после просмотренной выбирается следующая, если она есть.
- Прогресс хранится в SQLite отдельно для каждого аккаунта и доступен после входа на другом устройстве. Серии и разные источники/релизы имеют отдельные записи; смена перевода внутри серии сохраняет позицию.
- Сохранение каждые 10 секунд, при паузе, закрытии плеера и уходе со страницы. При аварийном закрытии браузера возможна потеря последних 10 секунд; без сети новые изменения не синхронизируются, плеер показывает ошибку.
- Устаревшая вкладка не перезаписывает более свежую запись другого устройства: при конфликте нажмите «Загрузить сохранённое».
- Серия отмечается просмотренной после 95% или вручную. «С начала» сбрасывает позицию и отметку. Следующая серия запускается автоматически с прежним переводом, если он доступен; также есть кнопка перехода.
- Shaka сохраняет управление с клавиатуры, перемотку на 10 секунд, громкость, субтитры, скорость и картинку в картинке при поддержке браузером.

Вкладка AniLiberty сохраняет отдельный каталог и локальное избранное. Старые позиции, которые хранились только в браузере, не переносятся автоматически в серверную историю.

### Прямое видео и ограничения

Python извлекает только HTML/JSON и видеоссылки. Сервер не проксирует и не сохраняет видео; HLS/MP4/DASH/WebM идёт от провайдера в браузер. Некоторые провайдеры привязывают ссылки к IP сервера, ограничивают CORS или требуют Referer/Cookie/User-Agent. Потоки с обязательными HTTP-заголовками явно отклоняются, поскольку браузер не может подменять их произвольно. При таких ограничениях выбирайте другой плеер/источник. Внешние страницы во фреймах не вставляются.

Доступность экстрактора не равна доступности каждого сайта. Блокировки, защита от ботов и изменения вёрстки дают понятную ошибку вместо бесконечной загрузки. Cookie браузера не извлекаются; решения CAPTCHA не автоматизируются. Нет загрузки модулей или произвольных URL по запросу посетителя.

Python-сервис не публикует порт на хост: обращаться к нему может Next.js через внутреннюю сеть Compose. **Не публикуйте порт 8000 и не маршрутизируйте `/extractor` напрямую из reverse proxy**: доступ пользователей контролирует Next.js, внутренний сервис доверяет идентификатору от него. Временные идентификаторы объектов принадлежат конкретному аккаунту и истекают через час без использования или после перезапуска сервиса. При сообщении об устаревших данных повторите поиск. Один процесс uvicorn обязателен, поскольку кэш находится в памяти.

### Локальный Python-сервис без Docker

```sh
python3.14 -m venv extractor/.venv
extractor/.venv/bin/pip install -r extractor/requirements.txt
extractor/.venv/bin/uvicorn service:app --app-dir extractor --host 127.0.0.1 --port 8000 --no-access-log
```

В `.env` сайта укажите `EXTRACTOR_URL=http://127.0.0.1:8000`. В Docker это значение автоматически переопределено на `http://extractor:8000`. Для обновления обоих сервисов: `docker compose up -d --build`.

## Защита и обслуживание

- Пароли: scrypt с индивидуальной солью. Сессии: случайные 256-битные токены, в SQLite хранится только SHA-256, срок 7 дней.
- Cookie: HttpOnly, SameSite=Strict, Secure по умолчанию. Отключать Secure можно только для локального HTTP.
- Все изменения требуют совпадения Origin с APP_ORIGIN. Попытки входа ограничены по логину и глобально, счётчики хранятся в SQLite. Лимиты: 10 на логин и 100 глобально за 15 минут. Для защиты от сетевого DoS добавьте лимиты reverse proxy.
- API не принимает произвольные URL для загрузки и не доверяет заголовкам пользователя/роли от клиента.
- SQLite содержит конфиденциальные данные. Резервируйте весь volume при остановленном приложении (включая WAL), либо делайте согласованную SQLite backup. Храните копии с ограниченными правами.

## Проверки

```sh
npm run build
npm run typecheck
npm test
extractor/.venv/bin/python -m unittest discover -s extractor -p 'test_*.py'
```

Тесты используют отдельную временную SQLite и локальный production-сервер: проверяют закрытые страницы/API, вход/выход, Origin, полномочия, создание аккаунта, отзыв сессий, ограничение попыток, изоляцию истории, точность позиции, продолжение из другой сессии и отклонение устаревших записей. Тесты Python отдельно проверяют цепочку экстрактора, изоляцию временных объектов, истечение кэша и отклонение несовместимых потоков. Они не подтверждают доступность CDN из сети вашего сервера. Перед приглашением друзей проверьте HTTPS, вход, запуск серии и восстановление резервной копии.

### Результат проверки интеграции

На момент интеграции живой поиск YummyAnime нашёл «Наруто», 220 серий, несколько озвучек и варианты «Субтитры». Для озвучки 2x2 получен HLS 720p с HTTP 200 и CORS; ссылка варианта «Субтитры» была извлечена, но его CDN вернул HTTP 500. AnimeVost вернул MP4 480p; AnimeGO выполнил поиск, но разбор серий завершился ошибкой. Просмотр полного эпизода в браузере не проверялся.

Воспроизводимая проверка Docker-связки без пользовательских данных:

```sh
docker build -t kadr-anime:local .
docker build -t kadr-extractor:local extractor
python3 tests/docker-extractor-check.py
```

### Проверка интерфейса и истории

На отдельном локальном стенде с тестовым аккаунтом и демонстрационным Sintel проверены: воспроизведение Shaka, полноэкранные настройки, восстановление сохранённой секунды после перезапуска сервера, смена дорожки без сброса времени, переход к следующей серии с выбранным переводом и ручная отметка просмотра. На ширине 390 px горизонтального переполнения нет. Это проверка приложения, а не гарантия доступности каждого внешнего аниме-источника.

### Safari и ошибки воспроизведения

Если браузер поддерживает HLS самостоятельно (в частности Safari), Shaka использует нативное воспроизведение HLS с прежним интерфейсом. Для записей отключён режим низкой задержки; восстановление зависания не перематывает видео вперёд (`stallSkip: 0`). Восстановимые ошибки сегментов показываются отдельно от критических; критическая ошибка содержит числовой код Shaka без подписанных CDN-ссылок. Устаревшие операции при смене потока не показываются как ошибки. Доступность каждой озвучки по-прежнему зависит от внешнего источника.
